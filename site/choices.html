Current export: iscrowd=0, no simplification. Pixel-edge fixtures: hand-authored, decoded by pycocotools. The boundary tracer and new export API are not implemented in #2714.

Why this matters

We found this cross-checking Roboflow polygon and mask exports. RF-DETR uses pycocotools: tools can disagree on ground truth before any prediction.

Old/new mask IoU: 4 × 4 square 0.64; 1 × 5 rectangle 0.42. Shape and offset matter; some masks are identical. These are mask differences, not measured mAP changes.

After switching: rerun mask-based evaluations using affected COCO ground truth, especially for small/thin objects. RF-DETR’s own loader and box-only evaluations using unchanged boxes are unaffected. New exports cannot repair old polygon files.

Maintainer decisions

Implementation, export default, hole policy, one PR or two. Also choose a documented direct correction (precedent: #2587) or a transition. The deprecation policy requires three minor releases before removing deprecated APIs; maintainers decide whether it applies here.

Why switching gains some alignment, but not universal compatibility

COCO paths in RF-DETR, Detectron2, and torchvision’s reference loader use pycocotools. Ultralytics’ helper truncates vertices before OpenCV fill; Supervision’s COCO loader rounds. These are operation-specific alignments.

Scope, sources, reproduce

Required export tests: single pixels, thin regions, holes, multiple parts and metadata. Pixel-edge polygons preserve a bitmap under the reference fill; neither polygons nor RLE recover the original continuous annotation from that bitmap.

Export evidence: Supervision’s COCO exporter. With no explicit crowd flag, it already selects RLE for some topologies; the examples keep iscrowd=0. Recent #2587 changed rounding, not the older inclusive fill.
