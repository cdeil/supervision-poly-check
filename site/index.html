What you are seeing
More than a shift.
The square from (1, 1) to (5, 5) describes a geometric region four units wide. COCO marks 4 × 4 pixels. Inclusive integer drawing marks 5 × 5.

      
01 / CONVENTION
Boundaries versus indices
COCO vertices are continuous object coordinates. Supervision rounds them to pixel indices and draws the boundary inclusively. A valid generic drawing rule becomes a compatibility problem when used to load COCO annotations.
02 / GEOMETRY
Area changes too
A translation preserves area. Here, extra boundary pixels enlarge the mask; slanted shapes can also lose reference pixels. A half-pixel offset alone does not reproduce COCO’s boundary rules.
03 / REFERENCE
Choose COCO’s convention
The pycocotools maintainer confirmed that this behavior is expected. The proposed Supervision change adds mask_rasterizer="pycocotools" to the COCO loader. Existing defaults and generic drawing keep their documented behavior.

    

    
Actual outputs, not an illustration
All 147 comparisons were computed with the real libraries: Supervision’s public DetectionDataset.from_coco and pycocotools’ frPyObjects → merge → decode. Every COCO reference mask was also checked against Supervision’s RLE loader and matched exactly. The after masks were measured through the patched public loader, checked against all 147 references, and verified to leave the default output unchanged. The browser displays these precomputed results; moving the slider selects a measured 0.05 px step.
OpenCV 5.0.0.93 · NumPy 2.5.3 · synthetic shapes only. Grid cells occupy continuous coordinates [x, x+1] × [y, y+1]; array indices start at 0. COCO’s implementation uses a 5× boundary rasterization, so exact edge behavior is more specific than a simple point-in-polygon rule.
